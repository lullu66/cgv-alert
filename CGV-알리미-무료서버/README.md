# 치이카와 CGV 텔레그램 알리미

PC를 꺼도 GitHub의 예약 실행으로 CGV 용산아이파크몰 시간표를 확인하는 개인 알리미입니다. AI나 OpenAI API를 사용하지 않습니다.

**현재 상태: 파일 제작과 자동 테스트 완료. GitHub 배포 및 실제 텔레그램 수신 검증은 아직입니다.** 로컬 Chrome의 실제 CGV 시간표 구조를 확인해 작성했습니다. GitHub 서버에서 CGV에 접속할 수 있는지는 최초 실행으로 확인해야 합니다. 접속 제한이 나오면 차단을 우회하지 않고 감시를 중지합니다.

## 기본 설정

| 항목 | 기본값 |
|---|---|
| 극장 | CGV 용산아이파크몰 |
| 영화 | 제목에 ‘치이카와’ 포함 |
| 확인 날짜 | 한국 시간 기준 오늘부터 7일 |
| 좌석 | 잔여 좌석 2석 이상 (연석 여부는 확인하지 않음) |
| 확인 주기 | 실행 중 1분 간격, 한 번 실행할 때 5회 확인 |
| 알림 | 본인의 텔레그램 개인 채팅 |
| 자동 예매 | 없음 |

처음 발견된 회차는 알려줍니다. 계속 조건을 만족하는 같은 회차는 반복해서 보내지 않습니다. 좌석이 기준 아래로 내려갔다가 다시 생기면 마지막 알림으로부터 60분이 지난 뒤 다시 알려줍니다. 전송 실패한 회차는 다음 실행에서 재시도합니다. 전송 직후 기록 저장 전에 실행이 중단되거나 GitHub 캐시가 삭제되면 중복 알림이 발생할 수 있습니다.

## 무료 실행 조건

- **공개 저장소 + 기본 Ubuntu 실행 환경**을 사용합니다. GitHub 공식 문서상 이 조합의 실행 시간은 무료입니다.
- 비공개 저장소에서는 작업 자체를 시작하지 않도록 설정했습니다.
- 유료 서버, AI 호출, 유료 실행 환경, 스크린샷·영상 보관을 사용하지 않습니다. 알림 기록만 작은 캐시로 보관합니다. 캐시의 무료 한도는 기본 10GB이며 한도를 확장하지 마세요.
- 프로그램 코드와 기본 영화·극장 설정, 실행 로그는 공개됩니다. 봇 토큰과 채팅 ID는 공개 파일에 넣지 않고 **GitHub Secrets**에 저장합니다.
- GitHub 예약 실행은 최소 5분 간격이라, 한 번 실행할 때 내부에서 **1분 간격으로 5회** 확인합니다. 실행 준비와 대기열 지연 때문에 실행 묶음 사이에 공백이 생길 수 있어 **24시간 정확히 매분 확인하는 것은 보장하지 않습니다.** 한 번의 날짜 전체 확인에 1분 이상 걸리면 완료 뒤 다음 확인을 시작하며 동시에 겹쳐 실행하지 않습니다.
- 공개 저장소에 60일간 활동이 없으면 GitHub가 예약 실행을 비활성화할 수 있습니다.

공식 안내: [무료 실행 조건](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [예약 실행 제한](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## 처음 연결하기

### 1. GitHub 준비

1. [GitHub](https://github.com/)에 로그인합니다. 무료 계정이면 됩니다.
2. 이 알리미 전용 **공개(Public)** 저장소를 만듭니다.
3. 이 폴더의 내용을 저장소 맨 위에 올립니다. 숨김 폴더인 `.github/workflows/monitor.yml`도 꼭 포함해야 합니다. ZIP 자체를 올리면 실행되지 않습니다.

### 2. 본인 텔레그램 봇 만들기

1. 텔레그램에서 공식 [BotFather](https://t.me/BotFather)를 열고 `/newbot`으로 봇을 만듭니다.
2. 발급된 토큰을 보관합니다. 이 채팅이나 공개 저장소에는 붙여 넣지 마세요.
3. 방금 만든 봇의 대화창을 열어 **시작(Start)**을 누르고 `알리미 연결`이라고 메시지를 보냅니다.
4. 함께 제공한 `텔레그램-ID-확인.cmd`를 실행해 토큰을 입력하면 개인 채팅 ID가 나옵니다. 토큰은 화면에 표시하지 않으며 디스크에 저장하지 않습니다. 공식 Telegram API에만 전송합니다. 기존 서비스와 공유하지 않는 새 전용 봇을 사용하세요.

### 3. 비밀 설정 저장

GitHub 저장소 → **Settings → Secrets and variables → Actions → Secrets → New repository secret**에서 다음 두 개를 만듭니다.

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | BotFather가 준 토큰 |
| `TELEGRAM_CHAT_ID` | 위에서 확인한 본인 개인 채팅 ID |

### 4. 첫 실행으로 검증

1. 저장소 **Actions → CGV Telegram Alert → Run workflow**를 엽니다.
2. `send_test`를 켠 채 실행합니다. 텔레그램으로 **연결 테스트** 메시지가 와야 합니다.
3. 실행 결과가 성공했고, 요약에 **마지막 정상 조회**가 기록됐는지 확인합니다. 테스트 메시지만 도착한 것은 CGV 조회 성공을 뜻하지 않습니다.
4. 정상 확인 뒤 **Settings → Secrets and variables → Actions → Variables**에 `ALERT_ENABLED`를 만들고 값을 `true`로 저장하면 예약 감시가 켜집니다.

CGV가 서버 접속을 차단한다면 이 무료 구성으로 정상 감시할 수 없는 상태입니다. 유료 상품을 자동 구매하거나 접근 제한을 우회하지 않습니다. 오류 알림 후 조회를 멈춥니다. 반복 실행으로 해결하려 하지 말고 CGV의 접근 허용 여부를 확인하세요.

## 설정 바꾸기

위 **Variables**에서 아래 값을 추가하면 됩니다. 비워 두면 기본값을 사용합니다.

| 이름 | 예시 | 의미 |
|---|---|---|
| `MOVIE_KEYWORD` | `치이카와` | 제목에 포함될 단어 |
| `MIN_SEATS` | `2` | 최소 잔여 좌석 |
| `START_DATE` | `2026-10-01` | 첫 날짜, YYYY-MM-DD |
| `END_DATE` | `2026-10-04` | 마지막 날짜, 최대 14일 범위 |
| `ALERT_ENABLED` | `true` | 예약 감시 켜기 |

날짜를 모두 비우면 매일 오늘부터 7일을 확인합니다. 시작일만 설정하면 그 날짜부터 7일을 확인합니다. 기간이 지난 뒤에는 조회하지 않습니다. 극장은 용산아이파크몰로 고정되어 있습니다.

**중지:** `ALERT_ENABLED`를 `false`로 바꾸거나 Actions에서 Disable workflow를 선택합니다. 진행 중인 실행까지 멈추려면 해당 실행을 Cancel workflow로 취소합니다.

**접속 제한 이후 재개:** 제한 해소를 확인한 다음 수동 실행에서 `reset_block`을 켭니다. 제한이 계속되면 다시 멈춥니다.

**텔레그램 메시지가 없을 때:** 봇 대화의 Start 여부, 토큰, 개인 채팅 ID와 Actions 실행 상태를 확인합니다. 전송이 실패하면 보낸 것으로 기록하지 않습니다. Telegram 공식 [Bot API 문서](https://core.telegram.org/bots/api)를 사용합니다.

## 검증 내용과 한계

- 실제 CGV 웹 화면에서 날짜 버튼, 선택 극장, 영화 제목, 상영 시간, 잔여 좌석의 구조를 확인했습니다.
- 날짜의 월·연도 변경, 심야 25시 표기, 좌석 기준, 중복 알림, 재입고, 전송 실패, 잘못된 화면 및 접근 차단 처리, 1분 반복 간격을 자동 테스트합니다.
- GitHub 클라우드 실행과 실제 Telegram 전송은 사용자 계정 연결 후 검증해야 합니다.
- CGV 화면이 바뀌면 수정이 필요할 수 있습니다. 좌석을 읽지 못한 경우 ‘좌석 없음’으로 오인하지 않고 오류로 처리합니다.

개발 확인: Node.js 22 이상에서 `npm ci`, `npm test`. 직접 실행하려면 `npx playwright install chromium --only-shell` 이후 Secrets와 같은 환경 변수를 설정하고 `npm start`를 실행합니다. 직접 실행한 경우에는 그 컴퓨터가 켜져 있어야 하며, GitHub 배포본은 사용자 PC와 무관하게 실행됩니다.
